   good what about stores bypassing loads? Does the thread get kicked out on a load miss or what?
A: Some late discoveries involving WAIT post synchronizations or (postsync). The idea is simple
   certain instructions cause the current thread to get into a WAIT state. These involve:
   --> Load dcache miss
   --> flush / trap / membar / CAS / prefetch
   --> Store buffer full
   --> Speculation (branch prediction)

   Side effect: Typically its a message sent from some low end data pipeline to the P stage
   saying knock this thread out. So in the case of a CAS or a load dcache miss the B stage 
   discovers the same and conveys the same to the P stage. In between P and B stage there could
   be one more instruction half executed... this is simply trashed. When the condition is fulfilled
   the thread gets back to the READY state again and the trashed instruction is refetched and reexecuted
   as you had imagined.

   So?
   Bottomline you cant have a store or load bypass a load miss because the thread would be in the WAIT
   state and the previous instruction would have been trashed.

   They act as trap syncs. Meaning they will inform the p stage to stop taking any more instructions

   saying the last store has completed.

   This *does not* flush the current thread

   Btw using traps triggered by precise instructions are called Precise Traps. They guarantee all

==== More IFU =====
-> Threads can move from ready to wait in the event of WAIT instructions. These instructions are
   called post sync (post synchronized) instructions meaning they go back to ready state when
   certain conditions are fulfilled. They include call/jmp/prefetch/atomics. Until these post sync
   conditions are complete the thread can be switched out and replaced with another in the instruction
   pipeline.
