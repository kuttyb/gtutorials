Software Component Lead (Fermi Thread Scheduling) Lead GPU Thread Scheduling Unit (Host) changes in Fermi from software. Work involved closely interacting with OpenGL/CUDA/DirectX  and HW teams to identify perf hotspots, pitfalls from previous generations and drive changes with HW and implement/support them in the Resource Manager driver code.

-> Support Multiple PBDMAs Previous architectures had a single instruction fetch/decode/feed to engine pipeline called PBDMA. This was unable to saturate PCIe bandwidth or keep GPU engines busy. My role here was to identify hotspots and work closely with hw to identify correct number of PBDMAs to fix above problems. Implemented SW support to split/ schedule instruction streams across PBDMAs and tweak timeslicing based on work load pattern.

-> Support Buffered Mode Scheduling Based on discussions with SW teams and HW, drove efforts to implement a new scheduling mode tuned for Vista WDDM. This allows OS to queue work on various engines in order without explicit synchronization. Implemented this queue called runlist, added efficient notifier support. Added support code in RM for new mode.

-> Fix Perf Problems in Buffered Mode Even though work is queued upfront by OS initial simulation showed hw was not taking advantage of this with better pipelining/prefetching. Worked with HW to add hints in RM to enable better prefetching / cache warming.

-> Optimize Runlist Data Structure Runlist is the SW queue that contains schedulable work items where CPU produces GPU consumes. Split global runqueue into multiple per node queues to avoid concurrency problems between Compute / Graphics and Copy Engines. Implemented double buffering to allow CPU to modify runlist without stopping GPU. Implemented an indexed bitmap for the data structure to get better CPU cache locality.

-> Efficient Software Method Handling Software methods (traps) allow pipelined execution of CPU code with GPU code. Implemented this handling to allow a bulk processing of sw methods from a single interrupt to reduce interrupt latency. Also added code for out or order SW method execution when SW methods are interleaved with hw methods.

-> Power Aware Scheduling (ELPG) This existing feature allows engines to power down during bursts of inactivity. My role here was to port this code to the new scheduler and make sure stop scheduling and revive scheduling of power gated engines worked correctly.  This feature was later staffed by an entire team and moved to microcode, helped them in this process.

-> Fault Recovery Worked closely with the hw team to design SW for recovery from page faults engine hangs and other conditions and identify changes required for new scheduling modes. Actual implementation was done by other members in my team.

-> Pipelined Page/Resource Swapping Worked with DX/HW to implement resource stealing from contexts that are not currently resident on the GPU and restoring them back right before they get to run. My contribution was injecting surrender resource / reclaim resource methods in existing instruction streams.
